## 验收步骤

- [x] 1. 环境准备：确认开发者工具选择 `cloud1-d9g4pv8m8457af92a`，`battle` 云函数已部署且可读写 `battle_rooms`；验证客户端直连 `battle_rooms` 被拒绝；确认 `createdAt` 索引和 `cleanup-battle-rooms` 每日定时触发器已生效；两台设备使用同一测试版本。
- [ ] 2. 创建邀请：账号 A 进入游戏，点击好友对战并成功创建房间；记录房间号，发出带房间参数的微信邀请。
- [ ] 3. 邀请进入：账号 B 从邀请卡片进入，成功调用 `join` 并进入同一等待房间；双方显示的对手身份正确。
- [ ] 4. 双方准备：A、B 分别点击准备，双方状态均同步为已准备；单次点击不重复扣除或改变其他状态。
- [ ] 5. 三秒倒计时：双方准备完成后服务端进入 `playing`，显示约 3 秒倒计时；倒计时结束前棋盘不可操作且不应上报有效比分。
- [ ] 6. 六十秒对局：倒计时结束后双方均可操作；以服务端 `startTime` 计时，约 60 秒到达后停止接受比分和道具请求。
- [ ] 7. 分数同步：A、B 各完成至少一次有效消除，双方看到对手分数更新；分数不倒退、不串号，异常增长请求被拒绝或不改变存档。
- [ ] 8. `freeze` 道具：一方仅使用一次 `freeze`；对手输入被短暂锁定，自己的道具数量只减少一次，效果结束后可继续操作。
- [ ] 9. `disturb` 道具：另一方仅使用一次 `disturb`；对手短暂需要 4 连消，效果结束后恢复普通规则，道具数量只减少一次。
- [ ] 10. 前后台切换：对局中将任一账号退后台并在短时间内回到前台；回到前台后仍能查询同一房间，比分、道具和倒计时无重复或回退。
- [ ] 11. 短暂弱网：对局中制造短暂网络抖动或断网后恢复；恢复后轮询继续，未产生重复道具、重复结算或错误加入其他房间。
- [ ] 12. 主动退出：另开一局，在对局中由一方主动退出；另一方最终收到对手离开并获胜的结算，房间状态变为 `finished`，退出方不能继续提交比分或道具。
- [ ] 13. 正常结算：重新创建一局并等待 60 秒正常结束；双方收到相互一致、视角正确的胜负/平局结果、比分和金币奖励，奖励只发放一次。
- [ ] 14. 重复查询幂等：对已结束房间重复触发 `query`（含重进或恢复轮询）至少 3 次；每次返回相同结算结果，状态不回退，金币、效果和玩家结果不重复生成。
- [ ] 15. 邀请过期：在测试环境构造或保留一个等待超过 10 分钟的房间；受邀者不能加入，房主轮询收到失效后显示明确提示并回到首页。
- [x] 16. 留存清理：在控制台放入 `createdAt` 早于 7 天的专用测试房间，等待定时器执行后确认该记录被删除，新房间不受影响，并在云函数日志核对删除数。
- [ ] 17. 失败证据记录：任一步失败时记录时间、版本、环境、房间号、账号/设备、操作步骤、截图或录屏、客户端日志及云函数返回/错误信息；不得以“日志打印失败但进程退出码为 0”作为通过依据。

# 留存内容一期：七日签到、每日任务、每周宝箱

状态：规则、概念及可运行界面已确认；用户要求标题加深并授权推进真实逻辑。周宝箱300/500/1000金币、入口名“每日金币”及可爱卡片方向固定。当前真实签到/任务/宝箱候选接入中，权威进度见 `project-status/development-steps.md`，未部署或上线。
日期：2026-09-23。适用：微信小游戏《猫猫开心消》。

## 1. 目标与范围

目标：让玩家愿意回来、领取后愿意开局、一周内愿意多次游玩。服务现有治愈猫咪主题及单人/好友60秒对战，不改变PvP主入口优先级。

本期只做七日累计签到、每日三项固定任务、每周活跃宝箱，以及共用的“每日金币”入口、领奖反馈和必要的保存/恢复。新增“活跃度”只是周进度，不是可消费货币。

不包含补签收费、广告翻倍、强制邀请、推送订阅、排行榜、随机抽奖、猫咪养成、关卡新机制或首页整体改版。每日挑战仍为每天一局、25步、2000分达标奖励500金币；现有金币/体力/道具价格不变。

## 2. 七日累计签到

按北京时间自然日，每日手动领取一次；按实际领取次数推进。漏签不清零，无补签入口。领取第7次后，下一自然日开始下一轮，不可当天连领新轮第1次。

| 累计次数 | 奖励初值 |
| --- | --- |
| 1 | 100金币 |
| 2 | 100金币 |
| 3 | 150金币 |
| 4 | 100金币 |
| 5 | 100金币 |
| 6 | 150金币 |
| 7 | 200金币＋锤子1个 |

一次循环共900金币＋1个锤子。第3、7次视觉突出；未到的格子可看奖励，不可领取。签到不要求先完成一局、看广告或分享。

当天签到成功自动计入20活跃度，领奖失败/待确认不提前计入。用户仅打开页面不算签到。

## 3. 每日小任务

一期固定任务，降低理解和调度成本，不先做随机任务池。三项共享正常游玩进度，目标是约2局完成，需在运行体验后校准，不能据此承诺时长。

| 任务 | 奖励初值 | 活跃度 |
| --- | --- | --- |
| 完成1局游戏 | 40金币 | 20 |
| 累计完成2局游戏 | 60金币 | 30 |
| 累计消除80枚棋子 | 60金币 | 30 |

- 支持单人闯关、每日挑战和好友对战；PvP只计算本人行为，不累计对手消除数，不要求一定玩某种模式。
- 完成1局即同时推进前两项；胜负均可，但须进行过有效操作并到达正式结算。重试请求、重复结算、主动退出、未开局退房不增加局数；复活仍是同一局。旧关重复挑战可计任务进度，不改变旧关不重复发通关金币的规则。
- 消除数按实际移除的棋子累计，包含连锁和特殊棋子效果，同一枚只计一次；换位、掉落、重排和障碍破层不单独计数。未正式结算的局暂不提交该局消除数；中断恢复后随原局结算提交一次。
- 任务完成自动获得金币与活跃度，不要求再次点三个领取按钮。结算页用一条简短反馈展示新增奖励；详情页显示进度或“已完成”。发奖待同步时必须明确显示“待同步”。
- 每日最多任务金币160、任务活跃度80；加签到当天活跃度上限100。任务进度以首次打开福利页之前的当天有效游玩也可累计为目标，只追踪功能启用后的事件，不追溯旧版本历史。

## 4. 每周活跃宝箱

北京时间周一00:00开始、下周一00:00结束。签到和任务完成自动累积活跃度；领取宝箱不扣活跃度，三档均可领取一次。

| 活跃度门槛 | 奖励初值 | 可达路径示例 |
| --- | --- | --- |
| 200 | 300金币 | 2天签到并完成全部任务 |
| 350 | 500金币 | 4天正常参与即可达到 |
| 500 | 1000金币 | 5天签到并完成全部任务 |

三个宝箱共1800金币。最高档只需5个完整活跃日，允许漏玩2天；只签到满7天为140活跃度，不能单靠登录领取宝箱。

宝箱手动点击打开，无随机奖励。上周已达标未领宝箱保留到本周结束，在同一页显示“上周待领”；到期前服务端固化领取资格。超过该期限失效，规则页与待领卡显示具体到期时间。领取上周宝箱不增加本周活跃度。

中途上线或周末首次进入的玩家使用同一周周期，明确显示周重置时间；七日签到独立累计，不跟随周一重置，也不因入场较晚清零。

## 5. 时间、断网与奖励一致性

- 服务器提供北京时间日期和周标识；改手机时间不能多领。签到以服务器接受领取的日期归属。
- 任务局数/消除数以正式结算所属日期归属。普通单人/PvP以结算时间为准；每日挑战保持已有挑战日期归属，跨日完成不计入次日任务。客户端须展示实际计入日期，避免误导。
- 离线可继续既有可用玩法，新增任务显示“待同步”；服务端未确认前不承诺金币到账。首版只接纳当天任务进度，过期的离线上报不补发旧日任务奖励；恢复联网时明确提示，原局通关/每日挑战奖励按原规则处理。此限制须在用户确认范围内，不能静默丢弃并显示已完成。
- 已确认完成但本地尚未到账的奖励不因换日失效，依收据继续恢复；它与尚未确认的离线进度不同。
- 同一签到日、任务日/任务编号、周/宝箱档位各有唯一领取凭据。重复点击、超时后重试、重启和跨周不重复发奖；先查询原结果，不另造收据。金币与道具组合奖励要能从中途存储失败恢复。
- 保留现有本地钱包边界：服务端负责福利资格/领取记录，本地应用奖励收据。不承诺换机或清除本地存储后恢复全部资产；领取记录防重不等于全量云钱包。完整云钱包另行评估。

## 8. 技术范围与信任边界

复用现有平台适配、云身份、服务端时间和收据模式；新增福利逻辑独立模块化，保留冻结daily-v1引擎。实施前addItem不具备组合奖励幂等能力，本地候选已增加coin.creditRewardOnce的金币＋锤子恢复日志；具体接口及证据见 `../contracts/retention-v1.md` 和 `project-status/development-steps.md`。

福利日期、计数上限、领取资格和凭据由服务端维护，仅服务端集合可写。任务进度按唯一局标识去重；每日/PvP优先复用现有服务端结算事实。

普通单人主要在本地运行，不能把客户端上报包装成服务端已证明其真实游玩。一期采用已确认的“客户端汇报单人行为＋服务端去重、合理范围检查、每日固定上限”方案；不为低额日常福利扩建单人完整重演服务，不向竞争排行开放这些记录。

若服务端现有结算不保留可信消除数，不能仅根据最终分数反推；需明确字段来源、客户端报告边界和上限。先验证接入成本，再固定消除任务实现合同。

新增身份关联的签到日期、每日汇总、周进度和奖励凭据纳入数据/隐私增量评审；明细仅保存业务必要数据，不保存原始触控轨迹。保留与清理期限必须覆盖领奖/幂等期限，并在实现前定案。新集合、云部署、分析上报均不由本规划自动授权。

静态主包最近记录约3.56MiB，余约451KiB，只作规划参考；优先复用素材，最终按微信实际包体复核。不依赖大背景图、额外SDK或网络字体。

## 9. 衡量与验收

主指标：北京时间日期口径的D1、D7留存。新用户按首次有效启动日期分组；回访指对应第1/7个自然日再次有效启动，同一用户去重。同步看既有玩家周游玩天数，避免只关注新用户。

行为指标：福利入口打开率、签到领取率、签到后同会话开局率、任务完成率、周宝箱各档达标/领取率。观察领取失败率、等待时长、每活跃用户新增金币、道具消耗、单人局数及PvP参与率，防止福利入口挤压主玩法。

分析事件建议仅含版本、匿名化身份、日期/周、功能/任务/奖励类型、结果类别和必要数值；沿用现有默认关闭的上报适配，授权配置及隐私说明完成前不得开启。无真实数据时不宣称留存提升。条件允许时分组比较，否则以上线前后同星期分组比较并说明混杂因素；至少等一个完整D7观察窗口和足够样本，不虚构提升幅度。

必须覆盖：漏签续进度、第7次及新轮边界、重复局结算、任务共享进度、失败正常计数/退出不计、跨午夜/跨周、上周待领到期、迟到回调、离线过期说明、金币＋道具中途失败恢复、连续重试不重发、旧存档无损升级。复用既有通过证据，仅补受影响测试。

客观放行：无重复/漏发的已确认奖励，异常可恢复，进度与收据一致，现有每日/PvP/单人不回归。视觉放行：真实Canvas样板和完整页面状态经用户确认；独立QA复核实现与证据，微信开发者工具和真机验收单列，不能用源代码测试替代。

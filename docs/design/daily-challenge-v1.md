# 每日猫咪挑战 v1 · 本地实现契约

依据已批准的 `docs/content-update-1235.md`。当前本地规则为每天一局、500金币及中断续局。平台授权与执行状态单独见`docs/release/daily-activation.md`；本文不代表已部署或发布。

## 固定引擎与规则

- 每天按服务端北京时间00:00换日，每位用户每天只有一局；8×8棋盘、五种普通猫咪、25次有效交换，无计时、体力、库存道具、复活或失败助力。中断后从已确认进度继续，失败或完成后当天不能重新开局。达到分数线后继续至25步耗尽。
- `js/core/daily-v1/`固定纯逻辑引擎快照，来源于本项目当前已验证GameCore/grid/config，保留MIT来源说明；独立实例RNG，禁止替换全局Math.random。普通关卡和PvP引擎不改动。相同日期/版本/操作得到相同棋盘、分数、统计。
- `js/core/daily-challenge.js`为唯一配置与建局/重演入口，输出version、date、seed、target、reward、level；每日引擎版本`daily-v1`，RNG与种子算法一并冻结。达标分通过固定策略模拟标定，模拟结果不冒充玩家胜率。
- 部署前通过本地打包工具将上述纯逻辑源复制到battle云函数的daily-engine目录，检查字节一致与重演一致；云函数不引用上传目录之外的文件。不得为后续普通关卡修改静默覆盖已冻结每日版本。

## 云端接口与存储

复用battle云函数动作：
- `dailyInfo {}` → `{ok:true, challenge, claimed, attempted, completed, runId?, score?, settlementId?,coinReward?}`。challenge由服务端当前日期生成；如当天已达标，返回其稳定收据供客户端恢复入账。
- `dailyStart {runId?}` → `{ok:true, runId, challenge, moves, expiresAt}`。事务保存用户哈希、起局日期和版本，期限7天。跨午夜继续属于原日期；新开局始终是服务端新日期；同日重复请求返回同一未完成局，带runId可续旧日未过期局。每人每分钟最多10次创建，失败给出明确错误。
- `dailyCheckpoint {runId,moves}` → `{ok:true,runId,moves,expiresAt}`，只允许追加并重演校验的操作前缀。
- `dailySubmit {runId,moves}` → `{ok:true,date,score,maxCascade,specialComboCount,qualified,settlementId?,coinReward}`。只接受25条 `{from:{row,column},to:{row,column}}`，逐步合法交换重演，不接受客户端score；拒绝未知版本、超期、身份不符、坐标/长度异常、非法交换。起局记录已经完成时重复提交返回同一结果。
- 首次达标为用户哈希+日期的事务幂等记录，500金币，重复提交只返回同一收据；历史300金币记录按原收据兼容。个人最佳仅本机承诺，不新增排行榜。
- daily_runs与daily_progress仅存校验所需用户哈希、日期/版本、创建/期限、结果和稳定收据；逐步操作保存在run的追加前缀中，完成后保留完整25步至定时清理，用于断线续玩与重放校验；不采集新身份资料。复用定时清理，30天删除旧记录，7天起局期限使已清理旧日期不可重新领奖。部署前须核实集合权限与相应隐私披露，当前没有线上效果。

## 客户端与本批边界

- 首页维持PvP最高优先级，增加较小每日入口。详情使用已接受的首页邀请函弹窗，无独立标题、不显示当前日期，显示25步、分数线、500金币、个人最好，以及加载/重试/今日已完成/进度同步/奖励待确认状态。
- 点击开始必须取得服务端run。客户端使用固定版本引擎、每步先本地持久化操作并追加服务端检查点，完成后持久化完整记录再提交；失败保留并重试，不声称奖励已到。
- 收据沿用`coin.creditOnce`；待领取和起局日期独立，旧日记录不覆盖新日资格。已成功入账后才显示已领取，存储失败保留可重试结果。
- 本批先完成可运行详情样板与其加载/开始/返回状态；结果页家族按原计划在用户确认详情视觉后扩展。范围不扩展到新素材、音频、广告或云钱包迁移。

## 本地验证与发布前披露

- 达标线2000：固定“首个合法交换”策略对2026年10月30个日期seed采样，分数1130–2490、均值1582.7、4/30达标；这是低策略工程基线，不代表玩家胜率。2026-09-22同策略25步为2130，浏览器和云端重演一致。后续调整必须在发布前改变daily版本或明确日期配置，不覆盖已有run规则。
- 云端快照同步由`tools/sync-daily-engine.cjs`生成，`--check`只读验证；client/cloud逐步网格/分数/统计一致，保留客户端和云端MIT notice。
- 发布前需运营方确认隐私增量：本机保存每日个人最佳、未提交操作记录和领奖凭证；主动进入/开始/提交每日挑战时云端取得OpenID并生成用户哈希用于绑定记录、限流与防重领，哈希仍属于用户相关信息；最多25步操作随检查点传输并存入daily_runs，用于中断续局和服务端重演；run/日成绩及收据依30天定时清理，未完成run有效7天，云服务日志/备份另按服务配置。PvP补充局次、累计胜场及续局确认字段。既有已确认隐私正文未自动冒充覆盖本增量，云部署与新增集合权限、发布和隐私声明仍须另行确认。
- 当前仅本地模拟服务，日期、版本、回放验证和收据逻辑已实现；没有创建线上集合或执行真实云调用。个人最好与金币仍是当前设备记录，不承诺跨设备钱包/纪录同步。
